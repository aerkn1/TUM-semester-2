# EOQ And EPQ Interactive Tutorial Design

## Objective

Create a standalone interactive HTML tutorial in the Supply Chain Management Topic 05 wiki folder. The page must explain EOQ and EPQ through editable, visual workflows that reproduce the logic and numerical tasks in the existing Topic 05 wiki note.

Target file:

`supply-chain-management/wiki/topic-05-eoq-production-systems-batching/eoq-epq-interactive-tutorial.html`

The artifact is for personal exam preparation. It must work by opening the file directly in a browser, with no local server, build step, package installation, or network dependency.

## Learning Goals

The tutorial should help the student:

1. Select EOQ, finite-horizon EOQ, or EPQ from the operational facts before choosing a formula.
2. Understand why EOQ balances recurring ordering cost against holding cost.
3. See why basic EOQ uses average inventory `Q/2`.
4. Separate order quantity from reorder timing when lead time or initial inventory exists.
5. Understand why finite-horizon EOQ requires an integer order count.
6. See why EPQ inventory builds at `p - lambda` and peaks below the production batch size.
7. Interpret outputs operationally instead of treating the page as a formula calculator.
8. Practice the exact workflows represented in the Topic 05 exercise answer guides.

## Scope

### Included

- A short model-selection router.
- Editable numeric inputs with immediate recalculation.
- Dynamic EOQ and EPQ inventory-profile diagrams.
- Dynamic holding-cost and setup-cost comparisons.
- Formula substitution steps with units.
- Operational interpretations and exam-trap warnings.
- All six wiki exercise workflows:
  - ABI Warehouses.
  - Tek Pak Beer Crates.
  - Kerosene Infinite Versus Finite Horizon.
  - Battery-Cell Line.
  - Router Make-To-Stock Factory.
  - Shovel Factory And Technology Adoption.
- A free-practice EOQ case initialized with `lambda = 9,600`, `K = EUR 80`, and `h = EUR 6`.
- Formula and preset-result self-tests embedded in the page.

### Excluded

- Stochastic safety-stock calculation.
- Newsvendor calculation beyond a short model-selection contrast.
- Persistent storage, accounts, analytics, or progress tracking.
- External chart libraries, fonts, frameworks, or CDNs.
- A local HTTP server or build pipeline.
- Changes to the Topic 05 spaced-repetition status.

## Page Architecture

The HTML file will contain semantic HTML, embedded CSS, and embedded JavaScript. The JavaScript will be split into small functions by responsibility even though it remains in one physical file.

### 1. Header And Orientation

- Page title and short purpose statement.
- A reminder to route the fact pattern before calculating.
- A compact legend for `lambda`, `K`, `h`, `p`, `Q`, `Imax`, `l`, `I0`, `t`, and `m`.

### 2. Model Router

An interactive decision sequence:

1. Is demand known and stable over the planning horizon?
2. Is replenishment instantaneous or produced gradually?
3. Is the horizon finite?
4. Are initial inventory and lead time relevant?

The router will recommend basic EOQ, EOQ timing extension, finite-horizon EOQ, or EPQ. Uncertain single-period demand will be routed away from EOQ/EPQ toward Newsvendor without implementing Newsvendor calculations.

### 3. Concept Comparison

A side-by-side visual explanation:

- EOQ: inventory arrives instantly, then depletes at `-lambda`.
- EPQ: inventory builds at `p - lambda` while production runs, then depletes at `-lambda`.
- EOQ holding cost uses `Q/2`.
- EPQ holding cost uses `Imax/2`.

### 4. Workflow Selector

A clear tab or button group will select one of seven workflows: the six wiki exercises plus free practice. Selecting a workflow loads its current values into editable controls and changes the visible result sections to match the task.

### 5. Editable Input Panel

Inputs will show labels, units, accepted ranges, and concise definitions. Input changes will recalculate outputs immediately.

Validation rules include:

- `lambda`, `K`, and `h` must be positive.
- EPQ requires `p > lambda` on a consistent time basis.
- Lead time, initial inventory, horizon, previous cost, and technology improvement cannot be negative.
- Warehouse count and finite-horizon order count candidates must be positive integers where applicable.
- Invalid values produce an inline explanation and suppress misleading results.

### 6. Calculation Ladder

Each workflow will follow the Topic 05 `CONTEXT.md` calculation standard:

1. Formula.
2. Substitution with units.
3. Arithmetic result.
4. Operational interpretation.

Important intermediate quantities will remain visible, including cost components, cycle length, order frequency, reorder point, first-order timing, continuous order count, integer candidates, production duration, and non-production duration.

### 7. Dynamic Visuals

Visuals will use inline SVG generated by JavaScript.

- EOQ sawtooth with peak `Q`, average line `Q/2`, cycle boundaries, and demand slope.
- EPQ triangle with production phase, depletion phase, `Imax`, batch size, production duration, and full cycle duration.
- Cost comparison bars for holding versus setup cost.
- ABI separate-versus-pooled annual cost comparison.
- Kerosene floor-versus-ceiling finite-horizon cost comparison.
- Battery and Shovel before/after or EOQ/EPQ cost comparison where the task supplies a baseline.

Visuals should scale from the calculated outputs rather than use fixed coordinates. Numeric labels must remain readable when values change.

### 8. Interpretation And Exam Traps

Each workflow will include a compact explanation of what the result changes operationally and what it cannot prove. Relevant warnings include:

- Lead time changes reorder timing, not basic deterministic `Q*`.
- Initial inventory delays the first replenishment.
- Finite horizon requires checking both integer neighbors of `m_hat`.
- EPQ requires `p > lambda`.
- EPQ uses `Imax/2`, not `Q/2`.
- Units must use a consistent time basis.
- EOQ/EPQ are inappropriate for one-time uncertain demand.

## Workflow Requirements

### ABI Warehouses

Inputs: warehouse count, demand per warehouse, `K`, and `h`.

Outputs:

- EOQ and cost per warehouse.
- Total separate-system cost.
- Pooled demand, pooled EOQ, and pooled cost.
- Annual and percentage savings.

Teaching point: pooling reduces duplicated ordering-system cost in the deterministic exercise setup.

### Tek Pak Beer Crates

Inputs: `lambda`, `K`, `h`, `I0`, lead time in weeks, and weeks per year.

Outputs:

- EOQ.
- Demand per week.
- Reorder point.
- First-order placement time.

Teaching point: quantity and timing are separate decisions.

### Kerosene Infinite Versus Finite Horizon

Inputs: `lambda`, `K`, `h`, season length in weeks, and weeks per year.

Outputs:

- Infinite-horizon EOQ, annual order frequency, and annual relevant cost.
- Horizon in years and continuous order count `m_hat`.
- Floor and ceiling candidate costs.
- Optimal integer order count and finite-horizon quantity.
- Percentage cost increase relative to the continuous infinite-horizon benchmark.

Teaching point: integer feasibility can move the finite-horizon solution away from the continuous optimum.

### Battery-Cell Line

Inputs: `lambda`, `p`, `K`, `h`, and weeks per year.

Outputs:

- EPQ batch size.
- Production-run duration.
- Maximum and average inventory.
- Annual holding, setup, and total EPQ cost.
- EOQ benchmark cost.
- Annual and percentage cost reduction.

Teaching point: simultaneous production and demand reduce the inventory peak.

### Router Make-To-Stock Factory

Inputs: `lambda`, `p`, `K`, `h`, `I0`, preparation lead time, and weeks per year.

Outputs:

- EPQ batch size.
- Weekly demand and preparation-start inventory.
- Time until preparation starts and production starts.
- Maximum inventory.
- Full cycle, production, and non-production durations.

Teaching point: preparation starts before inventory reaches zero so production begins at depletion.

### Shovel Factory And Technology Adoption

Inputs are divided into the current-state inference and proposed technology:

- Current `p`, `Imax`, and `Q` in weekly units.
- Weeks per year.
- Production-rate improvement percentage.
- New `K` and `h`.
- Previous annual relevant cost.

Outputs:

- Implied demand per week and year.
- New production rate per week and year.
- New EPQ, maximum inventory, cost components, and total cost.
- Maximum annual willingness to invest.

Teaching point: infer hidden demand from the inventory geometry, then value technology through avoided annual relevant cost.

### Free Practice

Default inputs: `lambda = 9,600` units/year, `K = EUR 80/order`, and `h = EUR 6/unit/year`.

Optional inputs: lead time in weeks and weeks per year.

Outputs:

- EOQ.
- Orders per year.
- Average inventory.
- Cycle length.
- Annual holding, ordering, and total relevant cost.
- Reorder point when lead time is positive.

Teaching point: rehearse the basic formula ladder from the saved clarification-session next prompt.

## Calculation Functions

The JavaScript will expose pure calculation functions inside the page script for:

- Basic EOQ metrics.
- Deterministic reorder timing.
- Finite-horizon EOQ candidates.
- EPQ metrics.
- Warehouse pooling.
- Shovel demand inference and technology valuation.

Rendering functions will consume calculation results without duplicating formulas. This keeps formula logic testable and prevents visual sections from drifting from numeric outputs.

## Numerical Conventions

- Calculations use full JavaScript floating-point precision internally.
- Display values use context-appropriate rounding, normally two decimals.
- Candidate comparison uses unrounded values.
- Currency is displayed as EUR where the source task uses euros.
- Rates always display their time basis.
- The page states that rounded operational quantities may require a managerial integer choice, while the tutorial preserves the mathematical optimum unless the task requires integer feasibility.

## Error Handling

- Invalid input displays next to the relevant control and in a summary status area.
- No chart or result is rendered from invalid or non-finite calculations.
- EPQ explicitly explains why `p <= lambda` is infeasible: production cannot build inventory while demand consumes output at the same or a faster rate.
- If initial inventory is already below the preparation threshold, the page reports that preparation must start immediately rather than presenting a negative waiting time as an operational recommendation.
- If pooling savings are negative under edited inputs, the page reports the calculated result without claiming pooling always saves money.

## Accessibility And Responsive Behavior

- Semantic headings, labels, fieldsets, tables, and status regions.
- Keyboard-operable workflow controls.
- Visible focus styles.
- Charts include text summaries for non-visual interpretation.
- Color is not the only carrier of meaning.
- Layout collapses to one column on narrow screens.
- No animation is required for understanding, and reduced-motion preferences are respected.

## Visual Direction

Use a restrained academic operations-dashboard style:

- Warm neutral page background.
- Dark ink text with blue for replenishment/production and amber for holding inventory.
- Clear cards, compact tables, and generous spacing.
- Monospace treatment for formulas and substituted values.
- No decorative imagery or external assets.

The visual hierarchy should lead from fact pattern to model, formula, calculation, diagram, and interpretation.

## Verification Strategy

### Automated Formula Tests

A separate lightweight Node test script will extract or evaluate the tutorial calculation module and verify expected results before implementation is considered complete. At minimum it will cover:

- Basic free-practice EOQ.
- ABI separate and pooled results.
- Tek Pak EOQ and timing.
- Kerosene floor/ceiling selection.
- Battery EPQ results and cost reduction.
- Router timing and durations.
- Shovel implied demand and willingness to invest.
- EPQ rejection when `p <= lambda`.

Tests will be written first and observed failing before formula implementation.

### HTML Verification

- Parse the file to confirm required sections and workflow controls exist.
- Confirm there are no external script, stylesheet, font, or image dependencies.
- Run the embedded self-tests and require a zero-failure result.
- Run a direct-browser smoke check if a suitable local browser tool is available; otherwise report that limitation explicitly.
- Run `git diff --check`.

## Acceptance Criteria

The feature is complete when:

1. The HTML file exists in the Topic 05 wiki folder and opens directly from disk.
2. All seven workflows load editable defaults and recalculate immediately.
3. The six exercise presets reproduce the wiki answer-guide values within display rounding.
4. EOQ and EPQ diagrams respond to edited inputs.
5. Invalid input cannot produce misleading numeric results or charts.
6. Each workflow includes formula steps, units, interpretation, and relevant exam traps.
7. The page contains no external dependencies.
8. Automated tests and HTML verification pass.
