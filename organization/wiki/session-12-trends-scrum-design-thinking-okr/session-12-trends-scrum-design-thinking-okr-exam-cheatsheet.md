## Core Exam Move

```text
Define method -> apply four-problem canvas -> state organizational implication
-> compare pros/cons -> assess whether it becomes a new form.
```

## Eden McCallum Network Example

Core logic:

```text
client problem -> internal partner defines project -> external experts selected
-> temporary project team -> team dissolves -> new expert combination next time.
```

Four-problem answer:

| Problem | Eden McCallum solution |
|---|---|
| Task division | consulting work split around client problem modules |
| Task allocation | experts matched from external network |
| Reward provision | project income, flexibility, reputation, interesting work |
| Information provision | partners, briefs, project routines, shared deliverables |

## Scrum

```text
Scrum = team-level agile framework for completing work through sprint cycles.
```

Roles/events/artifacts:

| Category | Elements | Function |
|---|---|---|
| Roles | Product Owner, Scrum Master, Developers | divide value, process, and product-work responsibility |
| Events | Sprint Planning, Daily Scrum, Sprint Review, Retrospective | rhythm, feedback, coordination, learning |
| Artifacts | Product Goal, Product Backlog, Sprint Goal, Sprint Backlog, Increment | make priorities, work, and progress visible |

Cycle:

```text
backlog refinement -> sprint planning -> daily scrum -> increment
-> sprint review -> retrospective -> next sprint.
```

Scrum canvas:

| Problem | Scrum answer |
|---|---|
| Task division | product/sprint backlog breaks work into items |
| Task allocation | Product Owner orders priorities; Developers self-organize |
| Reward provision | ownership, customer value, visible progress |
| Information provision | boards, events, artifacts, reviews, retrospectives |

Scaling Scrum:

```text
Multiple teams create technical, priority, and timing interdependencies.
```

Scaling practices:

- analyze interdependencies
- reconfigure resources
- mitigate interferences
- reconfigure schedules

## Design Thinking

```text
Design thinking = user-centered problem solving through discovery, iteration, visualization, prototyping, and testing.
```

Process:

```text
understand/empathize -> define -> ideate -> prototype -> test -> iterate.
```

Canvas:

| Problem | Design-thinking answer |
|---|---|
| Task division | discovery, definition, ideation, prototyping, testing |
| Task allocation | cross-functional participants bring user, technical, business knowledge |
| Reward provision | user impact, creativity, participation, visible prototypes |
| Information provision | research, visual artifacts, prototypes, user feedback |

Weak when:

```text
problem is already known and implementation discipline, regulation, scale, or reliability matter more than user discovery.
```

## OKR

```text
OKR = Objectives and Key Results; a strategy-implementation method for dynamic environments.
```

Objective:

- qualitative
- understandable
- meaningful
- directional
- connected to strategy/value

Key results:

- measurable
- outcome-oriented
- usually two to four per objective
- show progress toward objective

OKR canvas:

| Problem | OKR answer |
|---|---|
| Task division | strategy becomes objectives, key results, tasks |
| Task allocation | top-down and bottom-up alignment across levels |
| Reward provision | focus, meaning, progress visibility, ownership |
| Information provision | cycles, check-ins, dashboards, progress metrics |

Roofshot vs moonshot:

| Type | Use |
|---|---|
| Roofshot | 100% achievable commitments: operations, reliability, compliance |
| Moonshot | 60-70% success can be progress: innovation, exploration |

## Method Comparison

```text
Design thinking finds/tests problem-solution direction.
OKR aligns strategic priorities.
Scrum executes product work in short learning cycles.
```

| Method | Best for | Blind spot |
|---|---|---|
| Scrum | product execution and team learning | scaling and dependencies |
| Design thinking | ambiguous user problems and innovation | implementation and operational discipline |
| OKR | dynamic strategy implementation | metric gaming and overload |

## Trap Corrections

| Trap | Correction |
|---|---|
| "Scrum = project management tool." | Explain roles, events, artifacts, and coordination implications. |
| Ignoring scaling | Discuss interdependencies across teams. |
| "Design thinking = brainstorming." | Include user research, prototypes, testing, iteration. |
| "OKR = KPI list." | OKR links strategic intent to learning and progress. |
| Moonshots for operations | Use roofshots for binding operational commitments. |

## Last Line

```text
These methods become organization design only when they reshape coordination, decision-making, motivation, and information flows.
```
