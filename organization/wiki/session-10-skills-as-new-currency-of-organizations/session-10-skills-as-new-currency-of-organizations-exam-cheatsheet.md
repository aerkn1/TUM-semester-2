# Session 10: Skills As The New Currency Of Organizations - Exam Cheat Sheet

## Core Exam Move

```text
Explain job architecture vs skill architecture -> connect to HR/process decisions
-> show people consequences -> evaluate empowerment vs surveillance.
```

## Strategic Claim

```text
If work changes faster than job titles, organizations need a capability language that describes people, roles, development paths, and talent decisions more precisely.
```

Drivers:

- evolution of work
- AI impact
- regulation and fairness pressure

## Job Architecture Vs Skill Architecture

| Architecture | Organizes | Core elements |
|---|---|---|
| Job architecture | roles, hierarchy, relationship between positions | job function, family/sub-family, level, grade, career stream |
| Skill architecture | what people must know and do | core competencies, functional/job-family competencies, role-specific skills |

Trap:

```text
Job architecture is not an org chart. It classifies work, responsibility, value, progression, and pay logic.
```

## Skill Vs Competency

| Term | Meaning | Example |
|---|---|---|
| Skill | specific practical ability | API design, data analysis, stakeholder communication |
| Competency | broader role performance ability combining skills, behavior, and knowledge | leadership, customer orientation |

## Proficiency Levels

A skill framework is weak without behavioral depth.

| Level | Behavior wording |
|---|---|
| Basic | performs standard tasks with supervision |
| Advanced beginner | handles routine cases, asks for support when context shifts |
| Competent | independently applies the skill in normal conditions |
| Proficient | adapts across contexts and supports others |
| Expert | shapes standards and strategy for the capability |

Bad wording:

```text
understands API design
```

Better wording:

```text
independently designs versioned APIs that meet security and integration requirements.
```

## PayStream Case Route

Problem:

```text
Fast growth created inconsistent titles, unclear pay, unclear career paths, and turnover.
```

Family-clustering logic:

- Engineering/platform: backend, full-stack, DevOps/SRE, ML
- Product/design: product manager, technical product manager, UX/UI
- Risk/legal/compliance: risk analyst, compliance officer, legal counsel
- Growth/customer: growth marketing, account executive, customer success
- Leadership/support: engineering manager, assistant to board

Exam rule:

```text
There is not one perfect family answer; define the classification criterion and apply it consistently.
```

## HR Linkages

Job/skill architecture becomes organization design only when connected to:

- recruiting and selection
- performance management
- compensation and benefits
- learning and development
- succession planning
- workforce planning
- talent deployment

Risk:

```text
A taxonomy without decision rules becomes an HR database, not organization design.
```

## People Consequences

Use Self-Determination Theory:

| Need | Good rollout | Bad rollout |
|---|---|---|
| Autonomy | visible career choices | top-down skill scoring |
| Competence | support for mastery | public deficits without help |
| Relatedness | shared language for collaboration | ranking and mistrust |

Fairness questions:

- Which skills count?
- Who defines them?
- Is invisible coordination work valued?
- Can employees correct or challenge profiles?
- Are AI matching/scoring tools audited?

## Trap Corrections

| Trap | Correction |
|---|---|
| "Skills = database." | Skills are an organization-design language tied to decisions. |
| Confusing level and grade | Level = responsibility/complexity; grade = compensation class. |
| Vague proficiency | Define observable behavior. |
| "AI extraction is objective." | Discuss bias, transparency, accountability, privacy, appeal rights. |

## Last Line

```text
A skills-powered organization creates value only if transparency supports fair development and mobility instead of becoming hidden algorithmic control.
```
