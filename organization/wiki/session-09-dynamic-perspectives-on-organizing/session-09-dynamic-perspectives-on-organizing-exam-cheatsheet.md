## Core Exam Move

```text
Define change -> distinguish state/process -> select framework by problem
-> apply elements to case facts -> add blind spot and complementary lens.
```

## Organizational Change

```text
Organizational change = differences in an entity's state, form, or properties across time, plus the processes and mechanisms through which those differences emerge.
```

Separate:

1. What changed? State, structure, routine, identity, outcome.
2. How did it change? Sequence, interaction, feedback, resistance, adoption.

## Iceberg Model

| Perspective | Use | Limitation |
|---|---|---|
| Objectification | names change as object, variable, label | can hide temporal mechanisms |
| Distinction | compares before/after states or phases | can imply clean linear stages |
| Unfolding | explains interacting process over time | harder to analyze and manage |

Compact:

```text
Objectification names change. Distinction compares change. Unfolding explains change.
```

## Framework Router

| Framework | Best for | Main blind spot |
|---|---|---|
| Kotter | organization-wide mobilization, coalition, momentum, anchoring | can become top-down and linear |
| Lewin / Force Field | equilibrium, driving vs restraining forces | may oversimplify continuous change |
| ADKAR | individual adoption bottlenecks | underplays politics and structure |
| Bridges | psychological transition, loss, identity, ambiguity | underplays technical/structural design |
| Appreciative Inquiry | strengths-based, participative future building | can avoid conflict or harm |
| SCARF | social threat/reward: status, certainty, autonomy, relatedness, fairness | not a full implementation roadmap |

## Must-Know Elements

Kotter:

```text
urgency -> coalition -> vision -> communicate/enlist -> remove barriers
-> short-term wins -> sustain -> anchor in culture/systems.
```

Lewin:

```text
unfreeze -> change/move -> refreeze.
```

ADKAR:

```text
Awareness, Desire, Knowledge, Ability, Reinforcement.
```

Bridges:

```text
ending/letting go -> neutral zone -> new beginning.
```

Appreciative Inquiry:

```text
Discover -> Dream -> Design -> Destiny/Deploy.
```

SCARF:

```text
Status, Certainty, Autonomy, Relatedness, Fairness.
```

## AI Project-Management Tool Case Route

Case problem:

```text
Technical readiness is not adoption. Employees fear surveillance, team leads fear autonomy loss, old spreadsheets persist, and management wants visible progress.
```

Blended intervention:

1. define operational problem and limits of monitoring/data access
2. build coalition including IT, team leads, users, privacy/data representation
3. map driving and restraining forces
4. diagnose ADKAR by stakeholder group
5. pilot with autonomy, fairness, and surveillance safeguards
6. use existing good project routines as Appreciative Inquiry input
7. measure useful outcomes, not login counts
8. retire spreadsheets after trust and ability exist
9. reinforce through roles, measures, support, feedback

## Trap Corrections

| Trap | Correction |
|---|---|
| "Change = announcement/software installation." | Add adoption, routines, politics, identity, capability. |
| Listing Kotter steps | Link each step to case evidence. |
| Resistance is irrational | Diagnose status, autonomy, identity, fairness, incentives, workload. |
| Bridges transition = external change | Bridges is internal psychological transition. |
| SCARF as full plan | Use it as threat/reward lens, not roadmap. |

## Last Line

```text
Change answers are strongest when they combine a process framework with stakeholder-specific adoption, power, and identity diagnosis.
```
