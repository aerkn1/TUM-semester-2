# Session 02: Formal Organizational Design - Exam Cheat Sheet

Source note: [session-02-formal-organizational-design.md](session-02-formal-organizational-design.md)

Created: 2026-07-15

Use this sheet for rapid exam recall. It does not replace the full note and does not mark `First Pass` as completed.

## Core Exam Move

```text
Identify formal design element -> explain coordination/control logic
-> show tradeoff -> apply to case evidence -> avoid "rule exists = rule works".
```

## Weber And Formal Design

Bureaucracy baseline:

```text
fixed division of labor + hierarchy + general rules + technical qualification
+ fixed salary/career + separation between office and ownership.
```

Formal design matters because it structures:

- division of work
- coordination and control
- authority and accountability
- reliability, innovation, and adaptability

Exam-safe sentence:

```text
Formal design is the planned side of organizing, but its effects depend on how formal elements are enacted in practice.
```

## Four Formal Design Elements

| Element | Definition | Exam use |
|---|---|---|
| Rules | Explicit prescriptions: allowed, required, prohibited | control discretion; create reliability |
| Procedures | Formal step sequences for carrying out tasks | standardize process; may be bypassed |
| Roles | Expectations attached to positions | coordinate through monitoring, substitution, common perspective |
| Incentives | Instruments encouraging behavior | direct attention; may create unintended consequences |
| Structure | Grouping and reporting arrangement | fits coordination, uncertainty, size, and strategy demands |

Rule vs procedure:

```text
Rule = what is allowed/required/prohibited.
Procedure = how the task should be performed step by step.
```

## Structure Router

| Form | Best when | Strength | Weakness |
|---|---|---|---|
| Simple | small, founder-led, early stage | fast, flexible, committed | unclear responsibility, growth overload |
| Functional | few products, efficiency, deep expertise | scale and specialization | silos, slow response, hierarchy overload |
| Divisional | many products/regions/customers | product/customer responsibility | duplicated functions, weak cross-division integration |
| Matrix | dual demands such as product x function | shared expertise and dual coordination | conflict, dual authority, meeting burden |
| Horizontal | end-to-end processes/customer value | speed, teamwork, process focus | hard redesign; needs culture, rewards, IT, training |

Exam rule:

```text
No structure is best in general. Choose by coordination needs, uncertainty, size, product diversity, and strategic priority.
```

## Formal Design Does Not Equal Action

Pentland/Feldman idea:

```text
Procedures are generative systems. People interpret, adapt, ignore, or work around formal artifacts.
```

Use this when a case has:

- written procedures not activated
- roles unclear in practice
- escalation path available but not used
- incentives that narrow attention
- formal authority separated from expertise

## BP Deepwater Horizon Part 1 Route

Question:

```text
How did BP's formal organization shape what actors saw, decided, escalated, or failed to stop?
```

Case anchors:

| Feature | Case meaning |
|---|---|
| Hierarchy | BP Well Site Leaders had final authority over key judgments. |
| Procedures | Management of Change/control procedures existed but were not fully activated. |
| Reporting lines | Onshore expertise existed but escalation did not reshape action. |
| Diagnostics | Cement bond log was available but not run. |
| Accountability | Cost and schedule pressure made some outcomes more visible than others. |

Exam-safe interpretation:

```text
Do not reduce BP to individual error. Analyze hierarchy, procedures, reporting lines, diagnostic choices, and accountability pressure as interacting formal-design conditions.
```

## Trap Corrections

| Trap | Correction |
|---|---|
| Listing structures only | Always add the coordination problem and tradeoff. |
| "Rules prevent risk." | Rules help only if enacted, interpreted, and escalated in practice. |
| "Matrix is modern, therefore better." | Matrix fits dual demands but increases conflict and ambiguity. |
| "BP was one bad decision." | It was a formal system interaction under pressure and uncertainty. |

## Last Line

```text
Formal design gives the planned architecture of work; exam answers score when they explain how that architecture coordinates, controls, motivates, and misfires.
```
